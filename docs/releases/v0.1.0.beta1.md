# laiss-rails-cms 0.1.0.beta1

First public beta.

## What this is

A CMS engine for Rails, maintained by Laiss Labs. Content is modelled as **pages**
made of **elements**, and each element has typed **ingredient** fields. The admin
is a full editing environment for that structure; the public side is whatever your
host app renders.

Installed from git, not from RubyGems:

```ruby
# Gemfile — one gem. Translations and the authentication integration are inside it.
gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta1"

# Optional. Only the devise gem is separate; the integration itself ships inside
# laiss_cms. Leave it out to supply your own sign-in.
gem "devise", "~> 4.9"
```

Then, in this order:

```bash
bin/rails active_storage:install   # REQUIRED: image upload fails without these tables
bin/rails laiss_cms:install
bin/rails g laiss_cms:devise:install
bin/rails db:migrate
```

**`active_storage:install` is not optional and is not run for you.** The installer
does not add the ActiveStorage tables, so without it the engine boots but every
image upload fails. Run it first, before `laiss_cms:install`, so the migrations are
all present in one `db:migrate`.

The devise installer adds the `devise_for` route the admin sign-in needs; without
it there is no `/admin/login`.

## Requirements

- Ruby >= 3.1 (CI runs the matrix; 4.0.6 is the pinned development version)
- Rails >= 7.2, < 8.2
- Node >= 24 and pnpm 11 for the asset build, if you are building assets yourself
- An image processing backend (`image_processing` is a dependency)

## Versioning

**This is version 0.1.0, not 9.x.** The engine derives from an upstream CMS and
previously carried upstream's 9.x version string. laiss-rails-cms now has its own
independent sequence so the two cannot be confused. From here: semver, with
pre-releases as `0.x.y.betaN`. See `docs/versioning.md`.

While the major is 0, a breaking change may land in a minor bump.

## The naming contract

The fork's naming comes from a single mapping, `script/rebrand/mapping.yml`, and
`script/rebrand/verify` fails the build if a name appears in a casing or separator
form the policy forbids. `script/rebrand/leak_scan` fails the build if the upstream
name appears anywhere outside the three `LICENSE` files. Both run in CI.

Every existing configuration token name still resolves. Tokens are added, never
renamed, so a host app's overrides keep working.

## Admin

- One light theme. The light/dark toggle is gone; the admin does not follow the OS.
- Blue for the primary action and the current state; the brand accent is used only
  for the current state, and only as one signal among several.
- Borders are tiered: boundaries that carry meaning (form controls, focus) clear
  3:1, decorative edges (card outlines, table hairlines) stay light so nothing
  looks boxed. Both measured, not eyeballed.
- Radius, spacing, control heights and type are on one scale, in `rem`, so the UI
  scales with the reader's font size.
- The sidebar collapses on the page editor so the canvas gets the width, with a
  toggle to expand it again that is remembered for the session.

## Settings

The Settings screen reads and writes real engine configuration — site name,
default language, rows per page, upload count and size limits, page caching,
searchable checkbox, auto-logout. Values apply on the next request and are
persisted so they survive a restart.

Fields that are resolved at boot (default language name, storage adapter, image
output format) are shown read-only and labelled as requiring a restart. They are
not editable, because editing them would not take effect.

## The rich-text editor

Body fields are **intentionally limited to inline formatting and lists**: bold,
italic, link, bulleted and numbered lists, blockquote, inline code, undo/redo and
clear formatting.

This is a design decision, not a missing feature. Layout, headings and hierarchy
come from element definitions, so a body field has no business setting type size
or alignment — that would let a writer break the page's structure. Tables, colours,
fonts, alignment and source view are removed, their plugins are not loaded, and
`valid_elements` strips anything outside the allowed set even on paste or
programmatic insert. Paste is forced to plain text.

`laiss_cms/body-copy.css` provides public-side styling for every element the
editor can emit, so what a writer sees is what publishes.

## Known limitations

- **Beta.** The API and admin may change in a minor bump while the major is 0.
- **Authentication is opt-in.** `laiss_cms` expects a `current_user`. A Devise
  integration ships inside the engine but does nothing until you ask for it, so an
  app with its own sign-in is unaffected. Add this to the host app:

  ```ruby
  # config/application.rb, after `require "laiss_cms"`
  require "laiss_cms/devise"
  ```

  Without it there is no `LaissCms::User`, no `/admin/login` route and no admin
  user screen, and the admin raises `NoCurrentUserFoundError` until you define
  `current_user` yourself. The `devise` gem is not a dependency of `laiss_cms`.

- **Do not alias `current_user` to `current_laiss_cms_user`.** The engine's
  `current_laiss_cms_user` calls `current_user`, so an alias that points back at it
  recurses until Ruby raises `SystemStackError`. Supply a method that returns your
  user from your own auth system instead:

  ```ruby
  # app/controllers/application_controller.rb
  def current_user
    @current_user ||= User.find_by(id: session[:user_id])
  end
  ```

  If you use the bundled integration, you do not need to define anything: Devise
  provides `current_user` and the engine picks it up.
- **The element editor edits one page at a time.** There is no multi-page bulk
  editing.
- **No drag-and-drop page reordering across languages** beyond the existing
  sitemap tree.
- **Assets must be built** for a source install (`pnpm run build`). The built
  artifacts are committed, so a git install works without Node.
- **The `0.x` version means "young fork, expect movement"**, not "almost 1.0".
- **No RubyGems publishing.** By policy, permanently. Consume it from git.

## Verifying this tag yourself

GitHub Actions could not run on this repository when the tag was cut (jobs failed
before reaching a runner), so CI status is not the evidence for this release. The
evidence is a local run:

```bash
git clone git@github.com:JulioPapel/laiss-rails-cms.git
cd laiss-rails-cms
git checkout v0.1.0.beta1
bundle install && pnpm install
script/gates
```

`script/gates` runs all twelve gates and prints a pass/fail table with the counts.
It fails if a spec count drops, not only if a command exits non-zero, so a suite
that silently stopped loading is caught.
