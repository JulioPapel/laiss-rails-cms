# laiss-rails-cms 0.1.0.beta2

Packaging and correctness. **One gem to install**, authentication that stays out of
the way unless asked, and a test suite that no longer depends on the order files
happen to load in.

If you are upgrading from `0.1.0.beta1`, read
[Upgrading from beta1](#upgrading-from-beta1) first — it is a `Gemfile` edit.

## What this is

A CMS engine for Rails, maintained by Laiss Labs. Content is modelled as **pages**
made of **elements**, and each element has typed **ingredient** fields. The admin
is a full editing environment for that structure; the public side is whatever your
host app renders.

## Install

Installed from git, not from RubyGems:

```ruby
# Gemfile
gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta2"

# Optional. Only the devise gem is separate; the integration itself ships inside
# laiss_cms. Omit both if your app already has its own sign-in.
gem "devise", "~> 4.9"
```

Then, in this order:

```bash
bundle install
bin/rails active_storage:install              # REQUIRED: image upload fails without these tables
bin/rails "laiss_cms:install"                 # config, migrations, mount, demo files
bin/rails g laiss_cms:devise:install          # only if using the bundled sign-in
bin/rails db:migrate
bin/rails db:seed                             # REQUIRED: creates the site, language and root page
```

Two of those fail quietly if skipped, which is why they are called out here and in
the README:

**`active_storage:install` is not optional and is not run for you.** The
`laiss_cms:install` installer does not add the ActiveStorage tables, so without it
the engine boots but every image upload fails. Run it first, before
`laiss_cms:install`, so all the migrations are present for a single `db:migrate`.

**`db:seed` is not optional either.** The installer appends
`LaissCms::Seeder.seed!` to `db/seeds.rb` but does not run it. Run it and it still
creates nothing unless you have supplied `db/seeds/laiss_cms/pages.yml` — the
seeder returns early when that file is absent, silently and with no message. Write
a root page there first:

```yaml
# db/seeds/laiss_cms/pages.yml
- name: Index
  urlname: index
  page_layout: index
  title: Welcome
  children:
    - name: About
      urlname: about
      page_layout: standard
      title: About
```

Then `bin/rails db:seed` reports `Created page: Index` and the admin has a tree to
work with. Without it there is no site, no language and no root page — and because
a page needs a parent, the **New page** button produces nothing at all.

## Authentication is now opt-in

In beta1 the authentication code arrived by being installed. Now `devise` is not a
dependency of `laiss_cms` at all, and the integration does nothing until you ask
for it:

```ruby
# config/application.rb, after `require "laiss_cms"`
require "laiss_cms/devise"
```

Without that line there is no `LaissCms::User`, no `/admin/login`,
`/admin/signup`, `/admin/logout` or `/admin/passwords` route, and no admin user
screen. Everything else works. If you bring your own authentication, define
`current_user` and leave that line out.

This is what makes the engine usable in an app that already has a user model: it
will not create a `laiss_cms_users` table, will not register Devise mappings, and
will not add routes that collide with yours. The user migrations now ship with the
install generator rather than the engine's `db/migrate` for the same reason.

## Translating

All ten locales ship inside the engine; there is nothing to install and no
generator to run. The files are on `I18n.load_path` as soon as the engine loads.

Available: `en` `de` `es` `fr` `it` `nb-NO` `nl` `pl` `ru` `zh-CN`

Choose which the admin offers with the ordinary Rails setting:

```ruby
config.i18n.available_locales = [:en, :de, :fr]
```

## Fixed

**Redirects after an admin action went to the bare admin root.** The check that
decides whether a redirect target is safe interpolated the engine's mount path
(`/`) straight into a regular expression, producing `^//admin/` — a pattern that
can never match. Every accepted redirect therefore fell through to the fallback.
Deleting a user from `/admin/users` landed on `/admin` instead of the user list.
The pattern is now built from normalised parts, so a custom admin path
(`LaissCms.admin_path = "backend"`) and a mounted engine are both handled.

This was found by booting a fresh app, not by the test suite: the suite's own
configuration happened to mask it. That is the argument for the scratch-app check
below.

**`BaseMailer` raised in an application without `ApplicationMailer`.** The fallback
referred to `ActionMailer::Base` unqualified inside `module LaissCms`, so Ruby
looked for `LaissCms::ActionMailer` and raised. Apps that define
`ApplicationMailer` never reached the fallback, which is why this survived until a
minimal app tried it.

**The engine failed to boot where `config.assets` does not exist.** A Rails app
without sprockets or propshaft has no `config.assets`, and the locale and importmap
initializers assumed it. Both now check.

**A non-interactive install produced an app that could not seed.** The installer
asked for the primary language's code and name with `ask`, which returns `nil` when
stdin is not a terminal — CI, Docker, or any scripted install. That nil was written
into the generated initializer as `default_language.code = nil`, and `db:seed` then
died inside `create_default_language!` with `Validation failed: Name can't be
blank, Language code can't be blank` — an error naming neither the installer nor
the language. It now falls back to `en` / `English`, so `bin/rails laiss_cms:install`
runs to completion without a terminal. Found while running this release's install
proof with stdin closed.

## Test suite

The suite passed or failed depending on the random seed: 16 failures at seed 1234
on the beta1 code, and a different set at other seeds. Six independent leaks of
global state were responsible. **All six reproduced on `0.1.0.beta1`, so none was
introduced by these changes** — the fixes are in this release because a suite whose
result depends on file order cannot be used as evidence.

| Where | What leaked |
| --- | --- |
| `i18n_spec` | Wrote `@@available_locales` and reset it to `nil` instead of restoring it; the setter example had no cleanup at all |
| `engine_spec` | Ran an initializer that appends to the global `config.assets.precompile` and never removed the entry |
| `message_spec` | Reloaded `Message` under a stubbed mailer config; the reloaded class outlived the stub, so later examples saw a model that knew one field |
| `settings_spec` | "Restored" configuration by writing catalogue defaults, but `auto_logout_time` defaults to 30 there and is 40 in `config.yml`, so the cleanup itself corrupted the value |
| `attachments_controller_spec` | Spied with `expect_any_instance_of(ActiveRecord::Relation)`, which is process-wide |
| Picture fixtures | Every picture shared the name `"image"`, and the name becomes the filename in the variant URL. Two examples produced the same URL for different bytes, so the browser served a cached 1×1 where a 500×500 was meant |

Verified with four complete runs at seeds 1234, 98765, 4242 and 31337; 4408
examples, 0 failures each.

## Upgrading from beta1

Remove the two lines for the folded gems.

```diff
 gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta2"
-gem "laiss_cms_i18n", git: "…", tag: "v0.1.0.beta1", glob: "i18n/*.gemspec"
-gem "laiss-cms-devise", git: "…", tag: "v0.1.0.beta1", glob: "devise/*.gemspec"
 gem "devise", "~> 4.9"
```

Leaving them behind points Bundler at gemspecs that no longer exist, which fails
with a confusing path error rather than anything mentioning `laiss_cms`.

Then add the opt-in `require` if you use the bundled sign-in:

```ruby
# config/application.rb, after `require "laiss_cms"`
require "laiss_cms/devise"
```

If you had a `config/initializers/` file that loaded `laiss-cms-devise` by name,
the same `require` replaces it.

Run `bin/rails g laiss_cms:devise:install` again if you use the integration, then
`db:migrate` — the user migrations moved into that generator.

## Verifying this tag yourself

GitHub Actions could not run on this repository when this tag was cut: every job
fails before reaching a runner, with the reason GitHub gives in its own annotation
being that the account is locked for billing. CI status is therefore **not**
evidence for this release.

The evidence is a local run:

```bash
git clone git@github.com:JulioPapel/laiss-rails-cms.git
cd laiss-rails-cms
git checkout v0.1.0.beta2
bundle install && pnpm install
script/gates
```

`script/gates` runs all thirteen checks and prints a pass/fail table with the
counts. It fails if a spec count drops, not only if a command exits non-zero, so a
suite that silently stopped loading is caught.

Two scratch applications were also booted for this release:

- `gem "laiss_cms"` alone: boots, no `::Devise`, no `LaissCms::User`, no auth
  routes.
- `gem "laiss_cms"` + `gem "devise"` + `require "laiss_cms/devise"`: boots, 167
  engine routes including `/admin/login`, `/admin/signup`, `/admin/users` and
  `/admin/passwords`.

## Known limitations

- **Beta.** The API and admin may change in a minor bump while the major is 0.
- **`laiss_cms` expects a `current_user`.** Either opt into the bundled Devise
  integration or define the method yourself.
- **Do not alias `current_user` to `current_laiss_cms_user`.** The engine's
  `current_laiss_cms_user` calls `current_user`, so an alias pointing back at it
  recurses until Ruby raises `SystemStackError`. Supply a method that returns your
  user from your own store:

  ```ruby
  # app/controllers/application_controller.rb
  def current_user
    @current_user ||= User.find_by(id: session[:user_id])
  end
  ```

- **The element editor edits one page at a time.** There is no multi-page bulk
  editing.
- **No drag-and-drop page reordering across languages** beyond the existing
  sitemap tree.
- **Assets must be built** for a source install (`pnpm run build`). The built
  artifacts are committed, so a git install works without Node.

## Requirements

- Ruby >= 3.1
- Rails >= 7.2, < 8.2
- Node >= 24 and pnpm 11 for the asset build, if you build assets yourself
- An image processing backend (`image_processing` is a dependency)

## Versioning

`LaissCms::VERSION` in `lib/laiss_cms/version.rb` is the only place the version is
written. The gemspec reads it, and the git tag is `v` plus that constant. See
`docs/versioning.md`.
