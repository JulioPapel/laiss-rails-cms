# laiss-rails-cms 0.1.0.beta4

Corrective release. Two defects, both found by executing `ci.yml`'s steps instead of
reading them. Neither affects an installed app's behaviour.

## If you installed beta3

Bump the tag and run `bundle install`:

```ruby
gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta4"
gem "devise", "~> 4.9"   # optional
gem "propshaft"          # unless your app already has an asset pipeline
```

No migrations, no config changes, no data changes.

## The CI job for the devise specs could not have passed

`ci.yml` ran `bundle exec rspec devise/spec` from the repository root. That loaded
the **core** `spec/rails_helper.rb`, because `require "rails_helper"` is a load-path
lookup and rspec puts `./spec` first. The core helper never sets
`LAISS_CMS_DEVISE`, so the dummy app booted without the integration and five spec
files failed with `uninitialized constant LaissCms::Devise`.

From `devise/` the same require resolved to devise's own helper and everything
passed — which is why `script/gates` and local runs never showed it.

Fixed by making every job run `script/gates`, so there is one implementation of the
checks rather than two. The `counts` job is removed: it duplicated the example
floors with its own hardcoded numbers (4419/851 against the real 4410/846) and
would have failed on every run. `script/gates` already enforces those floors and
fails on a drop, not just on an error.

## Repository hygiene

33 coverage artifacts under `devise/coverage` were committed to git, including a
`.resultset.json.lock` and generated HTML. They are now untracked and ignored. Root
`/coverage/` was already ignored; `devise/` was not, and running the devise specs
from the root rewrites them.

## Verifying this release

```bash
git clone git@github.com:JulioPapel/laiss-rails-cms.git
cd laiss-rails-cms
git checkout v0.1.0.beta4
bundle install && pnpm install
script/gates
```

Fourteen checks, one command. `script/gates ruby`, `js`, `rebrand` and `scratch` run
the subsets CI runs, so what passes here is what CI would run — assuming CI can run
at all.

**GitHub Actions still cannot run on this repository.** Every job fails before
reaching a runner: the account is locked for billing. That is why this release's
verification is a cold clone rather than a green check mark, and why the steps above
are the evidence.

## Unchanged from beta3

The asset-pipeline boot check, the one-gem packaging, optional Devise, and the spec
isolation fixes. See [`v0.1.0.beta3.md`](v0.1.0.beta3.md) and
[`v0.1.0.beta2.md`](v0.1.0.beta2.md).
