# laiss-rails-cms 0.1.0.beta5

Corrective release. Five fixes, none of which change how an installed app behaves.

## If you installed beta4

Bump the tag and run `bundle install`:

```ruby
gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta5"
gem "devise", "~> 4.9"   # optional
gem "propshaft"          # unless your app already has an asset pipeline
```

**One requirement changed:** the minimum Ruby is now 3.4, up from a claimed 3.1.

No migrations, no config changes, no data changes.

## Minimum Ruby is 3.4

The gemspec said `>= 3.1.0`. That was never true in practice: 3.1 was never run, and
two dependencies exclude it at their newest versions (ransack 6.x and view_component
4.x both need 3.2), so the claim only held by silently downgrading them. A gemspec
requirement is a promise, so it now says what is tested: `>= 3.4.0`.

Ruby 3.4.12 and 4.0.6 are both exercised. The CI matrix covers 3.4/7.2, 3.4/8.1 and
4.0.6/8.1 — and the 3.4/7.2 leg was run before being added, not after.

## The guides could not be built at all

`guides/.vitepress/theme/index.js` still imported three advertising components that
were deleted during the rebrand. The VitePress build failed with
`Could not resolve "./SideBarAd.vue"` and had done since those components were
removed. Three links that legitimately point outside the guides tree
(`../CONTRIBUTING`, `../README`, and a `localhost:3000` example) also failed the
dead-link check.

Both fixed: the ad mounts are gone, and the dead-link rule now allows exactly those
three. `pnpm run guides:build` produces 29 pages.

## Fixes for contributors

- **`script/gates` names a missing tool instead of printing five bare failures.** On
  a machine without pnpm, the JavaScript gates each exited 127 and reported `FAIL`
  with no cause. It now checks prerequisites first and stops with "pnpm is not on
  PATH — install pnpm (CI does this with pnpm/action-setup@v4)", adding that nothing
  was verified.
- **`script/gates` warns when the active Ruby differs from `.ruby-version`.** Selenium
  resolves browsers per Ruby install, so a leaked PATH entry makes the browser-driven
  specs fail with "unable to find browser binary" — which reads as a broken suite. It
  cost real time three separate times.
- **The site-notification workflow can run outside a runner.** Its steps wrote to
  `$GITHUB_OUTPUT` under `set -u` and aborted when that was unset, so the workflow
  could not be exercised locally at all.
- **Action refs are pinned to released tags** rather than moving refs. Notably
  `ruby/setup-ruby@v1` was a **branch** — the repository has no `v1` tag. All four
  now name an exact version; the SHA-pinning trade-off is documented in `ci.yml`.

## Verifying this release

```bash
git clone git@github.com:JulioPapel/laiss-rails-cms.git
cd laiss-rails-cms
git checkout v0.1.0.beta5
bundle install && pnpm install
script/gates
```

Fifteen checks plus prerequisites. `script/audit` prints the release-readiness table
with live evidence in about a second.

**GitHub Actions still cannot run on this repository** — every job fails before
reaching a runner because the account is locked for billing. That is why the evidence
here is a cold clone rather than a green check, and why `docs/release-readiness.md`
marks the CI-dependent claims as unverified rather than assumed.

## Unchanged

The one-gem packaging, optional Devise, the asset-pipeline boot check, and the spec
isolation fixes. See [`v0.1.0.beta4.md`](v0.1.0.beta4.md) and earlier.
