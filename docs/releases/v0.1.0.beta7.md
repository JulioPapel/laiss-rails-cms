# laiss-rails-cms 0.1.0.beta7

The admin UI is reverted to its original design, and the sidebar is now near-black.

**Earlier betas have been withdrawn and their tags removed** — `v0.1.0.beta1` through
`v0.1.0.beta5` no longer exist. `v0.1.0.beta6` remains available. If you are on one of the
withdrawn versions, install this.

## Install

```ruby
# Gemfile
gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta7"
gem "devise", "~> 4.9"   # optional, for the bundled sign-in
gem "propshaft"          # unless your app already has an asset pipeline
```

```bash
bundle install
bin/rails active_storage:install
bin/rails laiss_cms:install
bin/rails g laiss_cms:devise:install   # only if using the bundled sign-in
bin/rails db:migrate
bin/rails db:seed
```

If you are using the bundled sign-in, `config/application.rb` must also load it,
**after** `Bundler.require`:

```ruby
Bundler.require(*Rails.groups)

require "laiss_cms"
require "laiss_cms/devise"   # only if using the bundled sign-in
```

Without that line a Gemfile that lists `devise` will not boot — the engine's
`devise_assets` initializer references `LaissCms::Devise`, which is only defined once
this file is required. Verified from a clean app: the failure is
`uninitialized constant LaissCms::Devise` raised from `lib/laiss_cms/engine.rb:41`.
An app that does **not** list `devise` boots fine without the require; it simply has no
sign-in.

Requires Ruby ≥ 3.4, Rails 7.2–8.1, and an asset pipeline.

## The theme attempt was reverted

Between beta6 and this release the admin was being restyled by adopting an external
Bootstrap theme ("Focus"). That work **rewrote the admin's markup** — views, components,
partials and the simple_form wrapper — page by page to match theme pages. It was the wrong
method, and it is reverted here in full rather than finished.

What was wrong: a UI lift should change how an interface looks, not change the interface.
Adopting a theme page by page replaced working structure with theme structure, adopted
Bootstrap, renamed the icon class, and changed the validation markup for all 71
`f.input` call sites. It also introduced a series of layout defects that then had to be
chased individually — a 900×900 logo, collapsed grid columns, 0×0 chart bars — all of which
were consequences of the replacement, not faults in the admin.

The admin is now restored to its original design:

- `app/stylesheets` — the 68 original files, byte-identical to the pre-theme state
- `app/assets/builds` — the original artifacts; the compiled `admin.css` is byte-identical
- every view, partial, component and the simple_form wrapper — restored
- `icon.js` emits `class="icon"` again
- Bootstrap 4.3.1 and Bootstrap Icons removed entirely, along with their licensing notices

Two widgets are **deliberately not** restored, because they made outbound network requests
on every dashboard load and this project does not do that: a news reader fetching
`alchemy-cms.com`, and an update checker fetching `rubygems.org`.

Features added during that period are kept, not deleted: the Settings screen, Events, the
bundled sign-in screens, user management and the notification mailers. Restoring a "clean"
tree would have removed working features, which would have been the same mistake in the
other direction.

## The one visual change: a near-black sidebar

The sidebar background is now `#0f1218`, and nothing else about the admin's appearance
changed.

The colour is the brand's own hue — `#00349c` is 220° — held at 7.5% lightness and 20%
saturation. A pure black reads as no colour chosen; a neutral grey loses the brand. This
keeps the largest colour surface in the admin in the same family as the rest of the palette.

Measured against the new background (WCAG AA needs 4.5:1 for body text, 3:1 for graphics):

| Pair | Ratio |
|---|---|
| nav labels | 21.00:1 |
| nav icons | 18.75:1 |
| Help / Leave | 21.00:1 |
| active label on the orange fill | 7.69:1 |
| orange fill against the sidebar | 7.69:1 |
| muted text | 10.05:1 |

Two contrast failures that existed **before** this release are fixed as a consequence of the
darker base: the active label was 4.37:1 on orange (below AA), and the sub-navigation hover
was white on a pale orange at 2.24:1. Both now pass.

Hover and active are also now distinct states. They previously shared one rule, so a hovered
menu entry looked selected; on near-black that would have made the whole menu look active.
Hover now lifts the surface slightly and only the current entry carries the orange marker.

This change is CSS only — no ERB, no class names, no custom elements. Verified by diffing the
compiled CSS: no declaration changed outside the sidebar's own selectors and tokens.

## Also in this release

- The per-screen migration-log gate is retired. It enforced a rule for a process that no
  longer runs; the script and the log are kept, with the gate commented and instructions to
  re-enable.
- Test baselines are back to the original suite's own counts: 4,399 specs and 823 JS tests.
