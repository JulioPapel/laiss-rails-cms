# laiss-rails-cms 0.1.0.beta6

**This is the only installable version.** Earlier betas have been withdrawn and their
tags removed from the repository — `v0.1.0.beta1` through `v0.1.0.beta5` no longer
exist. If you were on one of them, install this.

## Install

```ruby
# Gemfile
gem "laiss_cms", git: "https://github.com/JulioPapel/laiss-rails-cms.git", tag: "v0.1.0.beta6"
gem "devise", "~> 4.9"   # optional, for the bundled sign-in
gem "propshaft"          # unless your app already has an asset pipeline
```

```bash
bundle install
bin/rails active_storage:install
bin/rails laiss_cms:install
bin/rails g laiss_cms:devise:install   # only if using the bundled sign-in
bin/rails db:migrate
bin/rails db:seed
```

Requires Ruby ≥ 3.4, Rails 7.2–8.1, and an asset pipeline.

Because the earlier tags are gone, there is no upgrade path from them — install
fresh. `CHANGELOG.md` records what changed in each earlier beta for anyone who needs
the history.

## The migration tooling has been removed

This release removes the scripts that were used to derive this fork from its upstream
project. They should never have shipped in a public repository.

The decisive problem was `mapping.yml`: a complete old-name-to-new-name table,
covering every identifier, table prefix and path that changed. Publishing that
contradicts the policy this project enforces everywhere else — that the derivation is
disclosed in `LICENSE`, where the licence requires it, and nowhere else. A single file
that lists both names side by side discloses exactly what the policy exists to keep
out.

Removed in full:

```
script/rebrand/mapping.yml
script/rebrand/lib.rb
script/rebrand/apply
script/rebrand/verify
script/rebrand/leak_scan
script/rebrand/leak_scan_test
script/rebrand/self_test
script/rebrand/rename_paths.rb
script/rebrand/README.md
script/rebrand/gates          (its checks moved to script/gates)
```

### What still works

`script/gates` remains and is now the only gate implementation — specs, linters, the
asset build, the JavaScript suite, doc links, and a scratch-app check that the engine
refuses to boot without an asset pipeline. The example-count floors are unchanged.
`script/audit` still prints the release-readiness table.

CI is down to three jobs — `ruby`, `javascript`, `scratch` — and every one of them
calls `script/gates`.

### What is no longer automated

The rule that the upstream name appears nowhere outside the three `LICENSE` files
used to be enforced by a build-failing scan. That scan was part of this tooling and
is gone with it.

**This is now a review obligation, not a check.** `CONTRIBUTING.md` says so plainly
and gives the one-line search to run. Recorded here rather than quietly dropped,
because a policy with no enforcement deserves to be described accurately.

## Also in this release

- `script/gates` names a missing prerequisite instead of printing failures with no
  cause, and warns when the active Ruby differs from `.ruby-version`.
- The site-notification workflow can run outside a runner.
- Action refs in CI are pinned to released tags rather than moving refs.
- The guides build again; it had been failing since some components it referenced
  were removed.

## What still works, and what no longer exists

**This project does not use GitHub Actions.** Every workflow was moved out of
`.github/workflows/` into `ci-disabled/` at the repository root, where GitHub does not
read them. Verification is `script/gates`, run locally; deployment is **Coolify**
pulling this repository. Nothing here depends on a server-side check.

`ci-disabled/README.md` records what each parked file did, why it is parked, and
which of them had ever run successfully — none had.

## Verifying this release

```bash
git clone git@github.com:JulioPapel/laiss-rails-cms.git
cd laiss-rails-cms
git checkout v0.1.0.beta6
bundle install && pnpm install
script/gates
```

That is the whole verification story: there is no server-side check to wait for, so
the local result is the only result. The evidence for this release is exactly that
run, performed from a cold clone at the tag. `docs/release-readiness.md` records
which claims rest on a local run and which are simply not applicable now.
